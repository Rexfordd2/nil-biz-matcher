# DEMO + BETA Deployment Guide

This codebase supports two production surfaces from a single repository:

- **DEMO**: Public, lightweight, waitlist-only surface
- **BETA**: Full app with authentication gating

## Architecture

The split is controlled by the `APP_MODE` environment variable:
- `APP_MODE=demo` → Public demo mode with waitlist
- `APP_MODE=beta` → Full app with auth required

## Vercel Setup: Two Separate Projects

### Why Two Projects?

Deploying as two separate Vercel projects pointing to the same GitHub repo allows:
- Independent environment variables per surface
- Different domains for each surface
- Isolated deployment previews
- No code duplication or branching required

## DEMO Project Configuration

### 1. Create Vercel Project

1. Go to Vercel Dashboard → Add New Project
2. Import the same GitHub repository
3. Name: `athlete-ledger-demo` (or similar)
4. Framework Preset: Vite
5. Build Command: `npm run vercel-build`
6. Output Directory: `dist`

### 2. Set Environment Variables

**Production + Preview environments:**

| Variable | Value | Required |
|----------|-------|----------|
| `APP_MODE` | `demo` | ✅ Yes |
| `VITE_PUBLIC_MODE` | `true` | ✅ Yes |
| `VITE_WAITLIST_EMBED_HTML` | `<your Mailchimp embed>` | ⚠️ Recommended |
| `VITE_WAITLIST_EMBED_URL` | `https://forms.google.com/...` | Optional (fallback) |
| `VITE_DEBUG_KEY` | Leave unset | ❌ No |

**Optional (for enhanced demo features):**
- `VITE_GOOGLE_MAPS_API_KEY` - If you want live search in demo
- `VITE_SUPABASE_URL` - Only if you want server-side persistence
- `VITE_SUPABASE_ANON_KEY` - Only if you want server-side persistence

### 3. Configure Domain

**Recommended domains:**
- Production: `athlete-ledger.vercel.app` or `demo.athlete-ledger.com`
- Preview: Auto-generated by Vercel

### 4. Verify Deployment

After deployment, test:
- ✅ Landing page loads at `/`
- ✅ Waitlist embed is visible
- ✅ `/demo` route works
- ✅ `/app` redirects to `/demo` (DEMO mode restriction)
- ✅ No auth gates block access

## BETA Project Configuration

### 1. Create Vercel Project

1. Go to Vercel Dashboard → Add New Project
2. Import the same GitHub repository
3. Name: `athlete-ledger-beta` (or similar)
4. Framework Preset: Vite
5. Build Command: `npm run vercel-build`
6. Output Directory: `dist`

### 2. Set Environment Variables

**Production + Preview environments:**

| Variable | Value | Required |
|----------|-------|----------|
| `APP_MODE` | `beta` | ✅ Yes |
| `VITE_PUBLIC_MODE` | `false` | ✅ Yes |
| `VITE_DEBUG_KEY` | `<random-secret>` | ✅ Yes (for build security plugin) |
| `VITE_SUPABASE_URL` | `https://xxx.supabase.co` | ✅ Yes |
| `VITE_SUPABASE_ANON_KEY` | `eyJhbGc...` | ✅ Yes |
| `SUPABASE_URL` | `https://xxx.supabase.co` | ✅ Yes (server-side) |
| `SUPABASE_SERVICE_ROLE_KEY` | `eyJhbGc...` | ✅ Yes (server-side) |
| `AUTH_SECRET` | `<long-random-string>` | ⚠️ Recommended |
| `DATABASE_URL` | (if using Prisma) | Optional |
| `APP_URL` | `https://beta.athlete-ledger.vercel.app` | ⚠️ Recommended |

**Do NOT set:**
- `VITE_WAITLIST_EMBED_HTML`
- `VITE_WAITLIST_EMBED_URL`

### 3. Configure Domain

**Recommended domains:**
- Production: `beta.athlete-ledger.vercel.app`
- Preview: Auto-generated by Vercel

### 4. Verify Deployment

After deployment, test:
- ✅ Landing page loads at `/`
- ✅ No waitlist CTAs visible
- ✅ `/app` requires authentication
- ✅ Unauthenticated users redirected to `/auth/login`
- ✅ `/demo` redirects to `/` (BETA mode restriction)
- ✅ Login/signup flows work

## Environment Variable Summary

### DEMO Project

```bash
# Required
APP_MODE=demo
VITE_PUBLIC_MODE=true

# Waitlist (at least one recommended)

VITE_WAITLIST_EMBED_URL=https://forms.google.com/your-form

# Optional enhancements
```

### BETA Project

```bash
# Required
APP_MODE=beta
VITE_PUBLIC_MODE=false
VITE_DEBUG_KEY=<random-secret-for-build-security>

# Supabase (client-side)

VITE_SUPABASE_ANON_KEY=eyJhbGc...

# Supabase (server-side)
SUPABASE_URL=https://xxx.supabase.co

# App config

APP_URL=https://beta.athlete-ledger.vercel.app

# Optional features
VITE_GOOGLE_MAPS_API_KEY=AIza...
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=<user>
SMTP_PASS=<pass>
SMTP_FROM=noreply@example.com
```

## Local Development

### Test DEMO mode locally:

```bash
# Set env vars
export APP_MODE=demo
export VITE_PUBLIC_MODE=true

# Or create .env.local
echo "APP_MODE=demo" > .env.local
echo "VITE_PUBLIC_MODE=true" >> .env.local

# Run dev server
npm run dev
```

### Test BETA mode locally:

```bash
# Set env vars
export APP_MODE=beta
export VITE_PUBLIC_MODE=false

# Or create .env.local
echo "APP_MODE=beta" > .env.local
echo "VITE_PUBLIC_MODE=false" >> .env.local

# Add Supabase credentials
echo "VITE_SUPABASE_URL=..." >> .env.local
echo "VITE_SUPABASE_ANON_KEY=..." >> .env.local

# Run dev server
npm run dev
```

## Deployment Commands

### Deploy DEMO (manual):

```bash
# From project root
vercel --prod --project=athlete-ledger-demo
```

### Deploy BETA (manual):

```bash
# From project root
vercel --prod --project=athlete-ledger-beta
```

### Recommended: Use GitHub Integration

Both projects should use Vercel's GitHub integration for automatic deployments:
- Push to `main` → auto-deploys to both DEMO and BETA production
- PRs → auto-creates preview deployments for both projects

## Troubleshooting

### DEMO: "Waitlist embed not configured"

**Cause:** Missing `VITE_WAITLIST_EMBED_HTML` and `VITE_WAITLIST_EMBED_URL`

**Fix:** Set at least one in Vercel → Settings → Environment Variables → Production

### BETA: Build fails with "Debug routes must be protected"

**Cause:** Missing `VITE_DEBUG_KEY` in build environment

**Fix:** Add `VITE_DEBUG_KEY=<random-secret>` to Vercel env vars

### BETA: Users not redirected to login

**Cause:** `APP_MODE` not set to `beta` or `VITE_PUBLIC_MODE` still `true`

**Fix:** Verify environment variables in Vercel dashboard

### Routes behaving incorrectly (e.g., /app accessible in DEMO)

**Cause:** Stale build or environment variables not applied

**Fix:** Redeploy from Vercel dashboard or trigger new deployment via git push

## Migration Path

If you're currently running a single production deployment:

1. **Create DEMO project first** (less disruptive)
   - Use a new domain like `demo.athlete-ledger.com`
   - Set `APP_MODE=demo` + `VITE_PUBLIC_MODE=true`
   - Deploy and verify

2. **Convert existing project to BETA**
   - Keep existing domain (e.g., `athlete-ledger.vercel.app`)
   - Add `APP_MODE=beta` to env vars
   - Set `VITE_PUBLIC_MODE=false`
   - Add Supabase + auth env vars
   - Redeploy

3. **Update DNS/domains as needed**
   - Point main domain to BETA
   - Point demo subdomain to DEMO

## FAQ

**Q: Can I use one project with branch-based deployments instead?**

A: Not recommended. Environment variables would need to be managed per branch, and Vercel's per-branch env var support is limited. Two projects is cleaner.

**Q: What happens if APP_MODE is not set?**

A: Defaults to `demo` if `VITE_PUBLIC_MODE=true`, otherwise defaults to `beta`.

**Q: Can I add more modes (e.g., staging, alpha)?**

A: Yes, extend `src/config/appMode.ts` with additional modes and create corresponding Vercel projects.

**Q: Do both projects pull from the same GitHub branch?**

A: Yes, both pull from `main` (or whatever branch you configure). They differ only in environment variables.
